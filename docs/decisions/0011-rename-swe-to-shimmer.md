# 0011. Rename the `swe` placeholder to `shimmer`

Status: accepted (M1, #36) · Raised by Dev B (issue #15) · Signed off: Dev A, Dev B (CLAUDE.md §4,
changes `core` and `proto`) · Dev C notified (protocol.md, socket path, crate names)

## Context

CLAUDE.md's header said: "Binary name `swe` and crate prefix `swe-` are placeholders. Rename
once, early, everywhere." The product is now named Shimmer.

Timing matters. Most of these names are internal and could change at any time, but three are
not: the `SWE_*` environment variables (CLAUDE.md §10.1 calls the script ABI permanent), the
data directory, and the command that users' own scripts call through `SWE_SOCKET`. Today no
workspace scripts exist (M3 has not shipped), so changing them costs nothing outside this
repo. After M3 it would break every user's scripts.

## Decision

Rename everything, once, in one change:

| What | Before | After |
|---|---|---|
| Command, binary, `[[bin]]` | `swe` | `shimmer` |
| Crates | `swe-core`, `swe-proto`, `swe-store`, `swe-daemon`, `swe-mockd`, `swe-cli`, `swe-records` | `shimmer-core`, `shimmer-proto`, … |
| Rust paths | `swe_core::…` | `shimmer_core::…` |
| Env vars | `SWE_HOME`, `SWE_SOCKET`, `SWE_SESSION_ID`, `SWE_PLATFORM`, `SWE_WORKSPACE_ID`, `SWE_WORKSPACE_DIR` | `SHIMMER_HOME`, `SHIMMER_SOCKET`, … |
| Data dir | `~/.local/share/swe`, `~/Library/Application Support/swe` | `…/shimmer` |
| Socket | `$XDG_RUNTIME_DIR/swe/daemon.sock` | `$XDG_RUNTIME_DIR/shimmer/daemon.sock` |
| Windows pipe (docs only) | `\\.\pipe\swe-daemon` | `\\.\pipe\shimmer-daemon` |
| Mock socket example | `/tmp/swe-mock.sock` | `/tmp/shimmer-mock.sock` |
| README title | `PlatformDashboard` | `Shimmer` |

**These names are final.** `SHIMMER_*` and the data directory become part of the permanent
script ABI with M3. If a shorter command is ever wanted, add it as a command-pack alias
(CLAUDE.md §15.1) or a shell alias; do not rename the binary, the env vars or the directory.

**Older ADRs keep their history.** ADRs 0001–0010 are not rewritten; each one that mentions the
old names gets a one-line note pointing here.

**No data migration.** Nobody has shipped data yet. Existing developers move their own
directory by hand: stop the old daemon (`swe shutdown`), then
`mv ~/.local/share/swe ~/.local/share/shimmer` (Linux) or the macOS equivalent.

## How it was done

`.dev/rename-to-shimmer.sh` makes the change mechanically: `SWE_` → `SHIMMER_`, `swe_` /
`swe-` → `shimmer_` / `shimmer-`, and the whole word `swe` → `shimmer`, so words that only
contain the letters ("answer") are untouched. It skips `Cargo.lock` (regenerated by `cargo
build`), `docs/decisions/` and itself, and is safe to run twice. A branch that predates the
rename can run the same script before rebasing, which turns most conflicts into no-ops.
A handful of lines were fixed by hand: CLAUDE.md's header, the README title, a comment in
`crates/core/src/launcher.rs` that referred to the rename as upcoming, and the notes in README.md
and CONTRIBUTING.md saying the command would be renamed later. Hand-fixed lines never mention
the old name, so running the script again leaves them alone.

The script can be deleted once no branch from before the rename is still open. (Deleted under #51 once none was left; it's in the history at `ef6fc21`.)

## Not done here

- The CLI's help text and error prefix still spell out `shimmer` as literal strings rather
  than reading the binary's name. Changing the command again is not expected (see above), so
  this stays as is.
